# Scope and decisions

- Treat reviews, audits, explanations, reports, plans, and proposals as read-only unless the user also asks for implementation.
- Ask only when ambiguity materially changes the outcome, scope, risk, or authorization. Otherwise, state the assumption and proceed.
- Recommend one option when viable paths have meaningful trade-offs.
- For maintenance work, prefer targeted changes and established conventions.
- For an explicit redesign, rewrite, or compatibility break, reason from first principles. Do not make minimality or compatibility a hidden requirement.
- Apply a corrected decision criterion across the relevant scope, not only to the example that exposed the problem.
